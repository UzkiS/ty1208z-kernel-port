# RDA cfg80211 key callback regression, 2026-10-13

The artifact identity below records this milestone. The later
[operation regression](wifi-operations-20261013.md) supersedes the module and
patch while retaining these key-installation checks.

The actual optional Linux 6.12 USB module now validates cfg80211 key parameters
before logging/dumping or preparing a firmware request. This fixes offline
driver defects; the module has not been loaded on TY1208Z and there is no
firmware, scan, association or radio acceptance.

## Resulting behavior

- WEP40/WEP104/CCMP/TKIP lengths must match their cipher, rather than accepting
  any length from the generic copy helper. Empty/null keys, missing sequence
  pointers, negative/oversized sequence lengths and out-of-range key indices
  fail before issuing a command. BIP/WAPI have no verified command path and
  return unsupported instead of being sent as ordinary GTK data.
- The cfg80211 callback's explicit key-material debug dump is removed; the
  harness checks that accepted keys do not take that dump path.
- PTK installation requires a nonzero unicast peer. The pinned PTK wire format
  has no key-index field, so an extended nonzero PTK slot is rejected. Station
  GTK installation also requires a valid associated BSSID.
- Only STA/AP/P2P-client/P2P-GO roles reach these formats; the two interface
  role descriptions must agree. The old GTK default branch returned success
  without sending anything; unsupported roles now fail.
- Existing successful PTK/GTK WID selection, packed field positions, sequence
  padding, TKIP MIC order and 802.1X wait behavior remain covered by actual
  callback tests. Firmware errors propagate to the cfg80211 caller.
- When the optional `WLAND_AP_RESET` branch is compiled, cached AP GTK length
  changes only after the firmware call succeeds. That branch is disabled in
  the current USB build; the host harness explicitly compiles it to test both
  acknowledgment and error cases.

No new WID identifiers or guessed key-deletion/AP-stop payloads are introduced.
Validation of WEP-sized packing does not establish WEP firmware behavior. The
legacy deletion/iovar/AP-stop paths, management-key support and corresponding
capability advertising still require their own source/firmware work.

## Software evidence

`tools/test_wifi_keys.py` extracts the actual patched `wland_cfg80211_add_key`,
`wland_add_ptkey` and `wland_add_gtkey` functions. Protocol structures/WID
values come from the locked driver; cipher constants and interface enums come
from the pinned Linux tree. It compiles those callbacks with ASan/UBSan. Only
firmware transport, 802.1X waiting and kernel object plumbing are mocked.

The test executes 1344 role/cipher/length/pairwise combinations using exact
heap allocations, checks actual output payloads and input nonmutation, and
exercises firmware success/errors, sequence bounds, null inputs, invalid
indices/peers/BSSID, inconsistent/unsupported roles, interface-down and MLO
rejection. The marker is `RDA_KEY_CALLBACKS_PASS`. Existing real control-parser
and manufacturing/key-copy sanitizer checks also pass.

`make wifi-port` completes ARM compilation, full module link/modpost, exact
release/USB alias and manufacturing-symbol exclusion. The vendor source still
emits existing unused-function/missing-prototype warnings; this result is not
a warning-free whole-driver audit. Local lint, ordinary diagnostic build,
core time64 QEMU and guarded boot regressions pass.
