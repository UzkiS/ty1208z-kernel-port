# Physical RAM diagnostic boot — 2026-10-12

The corrected Linux 6.12.112 candidate booted on the user's TY1208Z CA /
Hi3798MV100 and provided a usable serial initramfs shell. This verifies one
single-core diagnostic image, not Hinas compatibility or a router installation.
The project sent no storage, persistent-environment or OTP/security writes.

## Transfer and boot

The existing CA Fastboot 3.3.0-dirty was preserved. Before transfer the CLI
rechecked its version, measured DDR bounds and unchanged stock bootcmd.
An ordinary ARM uImage was received by YMODEM at 0x01ffffc0, with load/entry
0x02000000. The host verified the reported size and device-side CRC before
sending bootm. No environment variable was changed.

## Initial failure and correction

The first candidate (SHA-256
`af5eb322b71a6df3e254a006a63daa716edfce88e71774935ae0df2ce34d448d`)
reached /init and initialized the MV100 timer, but could not open an initial
console. Its raw boot SHA-256 is
`37c290b65e2df87f137e601edf268ea10028c33497148e54287a33e63e901e9d`.

Our UART DT incorrectly overrode arm,primecell-periphid with 0x001fe011,
which does not match upstream PL011. The measured Hinas runtime DT had no
such override. Removing it allowed hardware ID discovery and bound PL011 rev2.
The corrected image changed the appended DTB; its raw zImage is unchanged.
Artifact checks now reject this override. A power cycle was required to leave
the first diagnostic because it had no usable console or network.

## Validation and limits

Local lint, diagnostic build, QEMU time64 and RAM boot gate tests passed.
The clean GitHub build and all checks also passed for `cfba617`:
[Actions run 38210743877](https://github.com/UzkiS/ty1208z-kernel-port/actions/runs/38210743877).
Serial PTY tests cover capture/identity gates, YMODEM handshakes/retries,
DDR/CRC mismatch rejection and complete fragmented/high-volume diagnostic
reports. They validate host tooling; the physical observations above establish
this board milestone.

The image has no eMMC, Ethernet, USB, Wi-Fi, SMP or loadable modules. It does
not mount the installed Hinas. The existing storage image is preserved, but
post-diagnostic Hinas reboot has not yet been recaptured. No flashable release
or complete Y2038 claim follows from this result. Raw logs and binaries remain
in ignored local evidence/artifact directories.
