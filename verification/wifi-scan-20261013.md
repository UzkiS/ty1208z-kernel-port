# RDA directed-scan error handling, 2026-10-13

The actual scan-completion wait previously returned the raw kernel wait result:
zero on timeout and positive remaining ticks on completion. Scan dispatch
treated zero as success. A multi-SSID request also continued after an error,
allowing a later request's result to overwrite an earlier failure. Its wait
flag was published only after sending the command, so a fast completion
could clear the flag before it was incorrectly set again.

## Changed behavior

The completion wait now returns zero on completion, `-ETIMEDOUT` on timeout
and the original negative interruption/error. It reads the wait flag once per
condition evaluation; the event handler publishes its clear before wakeup.
Directed dispatch publishes the intermediate wait before the firmware command.
The first failed firmware request or wait stops later SSIDs, clears pending
scan sequencing and retains the original error. Existing public-callback
error cleanup remains responsible for removing its timer and request.

All directed SSIDs are checked against the source's four-SSID limit and
32-byte payload capacity before any timer/request state changes. Null,
inconsistent or oversized requests return `-EINVAL`. Manufacturing/AP-mode
paths which would skip scanning return unsupported rather than success.
The active USB configuration does not enable smart-config/sniffer behavior.

No named-iovar mapping, firmware reply or radio capability was invented.
The current real startup blocker remains the unimplemented named-roaming
and PHY capability transport described in [startup](wifi-startup-20261013.md).

## Acceptance and limits

`test_wifi_scan.py` extracts the actual patched scan dispatcher and wait helper.
ASan/UBSan executes ordered one-to-four-SSID requests with full 32-byte payloads,
broadcast scanning, completion before the wait begins, failures at every
firmware/wait index, zero timeout and negative interruption, and whole-request
validation before side effects. It also checks the real event handler's
clear-before-wakeup source ordering. Marker: `RDA_SCAN_FAILURE_PASS`.

Firmware replies, timer operations and wait outcomes are fixtures. The test
does not exercise an actual USB command, asynchronous driver concurrency,
scan result parsing, scheduled scans, public cfg80211 ownership races or
radio output. It establishes these real functions' failure behavior only.
USB, chip/firmware identity, scan/association/AP and reconnect/performance
remain hardware-unverified.

The complete ARM module was rebuilt and linked, including all previous
WID/control/key/operation/startup sanitizers. `make lint`, `make build` and
`make test` passed, including core QEMU time64 and serial RAM-boot/TFTP gates.
Fresh preprocessing of the actual ARM/USB module confirms these changes are
in its active scan path. Remote CI acceptance of these new scan changes is pending.
