# TY1208Z CA 持久安装准备方案

这是准备方案；当前 RAM 包尚不能执行持久安装。
功能状态见[阶段报告](../verification/progress-20261014.md)。

拟沿用现有布局，在 eMMC p6 放内核，在 p9 放完整 OpenWrt rootfs、用户配置和
`/opt/docker`。p6 为 14 MiB 起、20 MiB 长；p9 为 610 MiB 起、6846 MiB 长。
该方案会替换现有 Hinas/Ubuntu 的内核与根文件系统。保留 p1–p5、p7/p8、已知成功的
CA fastboot；SD/TF 不作为此次安装目标。

| 准备项 | 已有证据／剩余条件 |
|---|---|
| 用户区备份 | 全部 7,818,182,656 字节已备份并独立哈希校验：`471a3b80e55c44823c601e4918504fa2977665021d8e36fcda7b79d185dc0695`。备份私有，不含 boot0/boot1/RPMB；方案不修改这些区域。 |
| 分区事实 | 9 分区已按 sysfs 扇区核对；实施时重新核对容量、起点、长度和未挂载状态，不能只依赖设备名。 |
| 恢复入口 | 保留 CA fastboot、TTL 和已接受的 RAM 启动／命令重启路径。原中文 RAM router 及配置恢复已实测。 |
| 存储写入 | 尚未实现或实测。当前请求过滤拒绝写入，即使清除只读标志也不能安装。需明确限定写入区域的驱动，以及必要的一次写入/读回/重启保留检查。 |
| 正式镜像 | 尚未生成。需完整已登记 rootfs、磁盘根启动，移除 RAM `/init` 的 tmpfs 复制路径，提供内核/DTB/rootfs 文件与哈希。现有 bootstrap 与补充 tar 不能直接刷入 p6/p9。 |
| 正常开机 | RAM `bootm` 接受 unsigned uImage，不能据此宣称 eMMC 自动启动也通过。需验证持久加载方式与内存保留，并保留进入 loader 的恢复入口。 |
| 原系统恢复 | 从完整用户区备份提取 p6/p9 恢复镜像，核对大小和范围，准备受限写回及读回哈希。恢复写回本身尚未实测。 |
| 授权 | 源码、离线编译、RAM 操作已有授权；真实存储写入及持久 boot 改动尚无授权。具体镜像、边界与恢复步骤准备完成后再确认。 |

顺序为准备完整镜像与恢复包，完成离线身份/大小/布局检查，给出待写文件、哈希和
p6/p9 替换范围；取得写入授权后验证受限可写路径，再安装并核对读回。
首次磁盘根启动通过后，只检查配置、Docker 数据保留和正常命令重启。
不重复已通过的内存压力、代理核心或 Docker 功能矩阵。

此方案不生成 OTP/eFuse、密钥、安全状态或 fastboot 替换命令，也不提供泛用整盘
覆盖命令。目前不承诺持久安装工期：存储/启动边界仍待实现。
