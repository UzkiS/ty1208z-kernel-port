## 完整安装的具体步骤与恢复

`tools/install_native_emmc.py` 的安装／恢复输入身份检查均通过，默认仅打印计划，
不连接盒子。完整操作需具体授权才使用 `--apply`；本次授权已收到。工具校验精确 RAM／磁盘内核、
压缩根镜像、控制工具、完整用户区备份记录、原 p6 镜像及已通过的单扇区 receipt。
实际写入前还会重新核验完整备份的原始字节 SHA-256；不会另造一份整盘备份。

1. 命令重启到同一已验收的可写 RAM 候选。保留紧邻重启的分配表、引导器检查和两个 CRC；
   用 SSH 校验 kernel APK、固定 p6/p9 起点／长度、未挂载、无 swap 及其他分区／SD 只读。
2. 只解锁 p9，流式解压并写入完整 7,178,551,296 B。fsync、清块缓存后读取完整 p9，
   SHA-256 必须匹配上表；然后锁回只读。此次写入包含文件系统空闲区，避免遗留旧元数据。
3. 只解锁 p6，写入内核和末尾对齐零字节，共 4,472,320 B。清缓存读回 SHA-256 必须为
   `917eeefdc242194c8ebbb14f746e2554c23327de2e7e30e20bc83f4442f69657`，再锁回只读。
   p6 其余空间保持原内容；已记录的引导命令读取 p6 的 20 MiB，`bootm` 使用 uImage
   头声明的内核长度。实际磁盘根启动仍待验收。
4. 写入工具保存私有 receipt 后结束，不自行重启。确认两分区的校验与锁定结果后，
   使用已测命令重启路径及现有 p6 加载方式进行第一次磁盘根启动；不修改 boot 环境。
5. 仅验收真实 ext4 根、配置和 Docker 数据保留以及正常命令重启。成功后才算完整安装完成。

写入／读回失败时停止，不继续写下一分区或重启。每段的 shell trap 尝试只读锁定；
不把 trap 当作已确认恢复。保留当前 RAM 管理连接、备份和日志，核清实际状态后，
在已授权的恢复范围内使用同一工具的 `--mode restore`：只写回完整备份中 610 MiB 起的
6846 MiB p9，再写回原 p6 的完整 20 MiB；各自 fsync、清缓存、SHA-256 读回并锁定。
恢复工具已准备，但完整恢复写回尚未实机验收。掉电可能打断写入或恢复。

首次磁盘根启动通过后，只检查配置、Docker 数据保留和正常命令重启。
不重复已通过的内存压力、代理核心或 Docker 功能矩阵。

完整安装将替换 Hinas/Ubuntu 的 p6 内核和 p9 根文件系统。其他用户区分区、CA fastboot、
SD、boot0/boot1/RPMB 和安全状态保持原样。完整写入及读回的耗时取决于单扇区 PIO 速度，
尚无实测工期。
