# TY1208Z CA 持久安装准备方案

这是准备方案。完整磁盘候选已离线生成，尚未实机启动或获得写入授权。
功能状态见[阶段报告](../verification/progress-20261014.md)。

拟沿用现有布局，在 eMMC p6 放内核，在 p9 放完整 OpenWrt rootfs、用户配置和
`/opt/docker`。p6 为 14 MiB 起、20 MiB 长；p9 为 610 MiB 起、6846 MiB 长。
该方案会替换现有 Hinas/Ubuntu 的内核与根文件系统。保留 p1–p5、p7/p8、已知成功的
CA fastboot；SD/TF 不作为此次安装目标。

## 下一步只申请一次 512 字节验证

`tools/probe_native_emmc_write.py` 默认只输出计划。获得特定写入授权后，才在精确
可写 RAM 内核中验证身份、容量、p9 范围、未挂载和 SD 只读状态。预先把 p9 最后一个
扇区（用户区 LBA 15,269,887，字节偏移 7,818,182,144）的原 512 字节保存到电脑，
写一个不同模式、fsync、清缓存读回，再立即写回原 512 字节并读回比较，重新锁为只读。
失败时保留原扇区与记录，不继续写入或自动重启。脚本的 EXIT/signal trap 也尝试恢复。
这是实际 eMMC 写入，掉电仍可能中断恢复，因此需要明确授权；它不改变持久 boot。

验证通过后再给出完整安装写入步骤与单独授权请求，覆盖范围仅限 p6/p9。
首次磁盘根启动通过后，只检查配置、Docker 数据保留和正常命令重启。
不重复已通过的内存压力、代理核心或 Docker 功能矩阵。

此方案不生成 OTP/eFuse、密钥、安全状态或 fastboot 替换命令，也不提供泛用整盘
覆盖命令。目前不承诺持久安装工期：存储/启动边界仍待实现。
