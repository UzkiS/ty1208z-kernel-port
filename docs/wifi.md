# Wi-Fi 适配：待确认芯片

用户已将板载 Wi-Fi 纳入目标。当前没有本机 `lsusb`、SDIO ID、启动日志
或芯片丝印；尚不能承诺联网或 AP 模式已经支持。

## 离线已发现

Hinas 本地 rootfs 包里存在 `rtl8188eu.ko` 和 `rtl8188fu.ko`，vermagic 为
`4.4.35_ecoo_81082668 SMP mod_unload ARMv7 p2v8`，与本地 Hinas 内核匹配。
它们是 USB 驱动，不是当前机器使用这两种芯片的证明。实际机器运行的内核或
根文件系统也可能与这个包不同。

| 驱动线索 | 模块 alias 中的 USB ID | Linux 6.12 候选 | 主线固件名 |
|---|---|---|---|
| RTL8188EU | `0bda:8179`、`0bda:0179`、`07b8:8179` | `rtl8xxxu` 的 8188e 支持 | `rtlwifi/rtl8188eufw.bin` |
| RTL8188FU | `0bda:f179`，厂商接口 | `rtl8xxxu` 的 8188f 支持 | `rtlwifi/rtl8188fufw.bin` |
| RDA5995，来源不确定的 Android 备份 | `1e04:8888`，`rdawfmac.ko` | 在所查主线无线目录未找到对应驱动 | 备份中存在 rda5995 系列固件 |

6.12 的 `rtl8xxxu` USB 表使用接口类型匹配，必须核对完整设备/接口描述，
不能只看 VID/PID。该版本 8188f 子驱动声明了 `supports_ap`；8188e 子驱动
没有同样声明。因此“能无线联网”和“能发热点”应作为两个验收项。

## 后续实施

先读取原 Hinas 的 USB/SDIO 枚举、内核日志、模块依赖和错误信息。若实际是
上述 Realtek USB 方案，可优先尝试现代主线驱动，并匹配许可明确的固件包。
必须先完成 USB 控制器、PHY 时钟/复位及供电验证，内核版本升级不会自动实现这些。

若是其他 USB 芯片，按真实 ID 选择驱动；若走 SDIO，还要先适配相应 MMC/SDIO
主控、供电与中断。只有主线不支持时再评估外置驱动的维护成本。

Wi-Fi 后续为可选构建，不并入当前单核、无 USB/网络的诊断候选。验收包括
扫描、加密联网、DHCP、DNS、数据收发、断线重连和冷启动；AP 模式与 Passwall
流量路径分别验证。旧 4.4 模块不能直接装入 6.12。
